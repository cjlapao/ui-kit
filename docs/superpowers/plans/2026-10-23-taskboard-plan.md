# TaskBoard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A React `TaskBoard` (kanban columns + swimlanes) with real-time drag and drop, a
transport-agnostic collaboration layer that shows peers' drags and locks held cards, and a
kit-docs page shaped like `ComboboxPage`.

**Architecture:** A framework-free engine lives in `common/taskboard/`. It holds the data model,
bucketing, move validation, drop resolution, collab reducer, history, tokens and fixtures. A thin
React layer in `react/src/components/TaskBoard/` renders it inside `Panel` and wires
pointer/keyboard/collab. This mirrors `common/gantt` + `react/src/components/Gantt`.

**Tech Stack:** React 19, TypeScript, Tailwind v4 (kit safelist), Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-23-taskboard-design.md`

## Global Constraints

- `common/` never imports React or the DOM, except `createBroadcastChannelTransport`, which
  touches the global `BroadcastChannel` only when called.
- Colour is `TrueColor` only. Token maps are generated by iterating the colour argument (Gantt
  style), and every dynamic class goes into `scripts/generate-safelist.mjs` under a `// TaskBoard`
  section. Then run `node scripts/generate-safelist.mjs` and rebuild the kit CSS
  (`cd react && npx @tailwindcss/cli -i ./src/styles.css -o ./dist/index.css`).
- Container = `Panel`. Pass through `variant` (default `"elevated"`), `tone`, `corner`,
  `padding`, `glassOpacity`, `vibrancy`, `specularMode`, `loaderType`. Add a `plain` variant.
- Copy colour comes from `useSurfaceText()` (`react/src/contexts/SurfaceContext.tsx`). The board
  body must be a child component of `Panel`. Never use `text-slate-*` / `text-neutral-*`.
- Built-in strings go under `kit.taskboard.*` in `common/i18n/builtIn/{en,de,es,fr,pt}.ts` and
  are read with `useKitT()`. A `labels` prop overrides them.
- Collab constants: heartbeat `PRESENCE_HEARTBEAT_MS = 5000`, lock expiry
  `LOCK_TTL_MS = 8000`, hover publish throttle ≤ 20 Hz (`HOVER_THROTTLE_MS = 50`).
- Touch grab long-press `TOUCH_GRAB_DELAY_MS = 250`.
- File writes must be atomic (Write/Edit tool, or temp + `mv`): a Vite dev server is running.
- React only. Vue is a step behind (say so in `Learnings.md` and on the docs page).
- Do not commit unless Carlos asks. Each task's last step is "stage for review" instead.

## Review Focus

1. **A peer's grab arrives after my own grab started but carries an earlier `at`.** My drag must
   cancel and the card must spring back. Neither client may end up dropping. The test lives in
   Task 3 (`presenceReducer` race) and Task 9 (component cancels the local drag).
2. **The `cards` prop changes mid-drag** (a remote commit lands while I am dragging a different
   card). My clone and target slot must survive, and the dragged card must not jump. Test in
   Task 7.
3. **A drop onto a full-WIP column, or one whose `accepts` excludes the source.** There must be
   no insertion line, and the drop is a no-op that emits nothing. Tests in Task 2 and Task 7.
4. **`onBeforeMove` rejects, or its promise throws.** The card returns to its exact original
   index, `onCardsChange` is never called, and the pending state clears. Test in Task 7.
5. **The transport handler fires after unmount, or a peer sends malformed/unknown events.** There
   must be no setState-after-unmount, and unknown event types are ignored. Tests in Task 3 and
   Task 9.

### Task 2: Engine — move validation, apply, drop resolution, keyboard targets

**Files:**
- Create: `common/taskboard/move.ts`
- Test: extend `taskboard-engine.test.ts`

**Interfaces:**
- Consumes: Task 1 types, `bucketCards`, `bucketKey`.
- Produces:
  - `type MoveVerdict = { ok: true } | { ok: false; reason: "locked-card" | "locked-column" | "locked-lane" | "not-accepted" | "wip-column" | "wip-lane" | "held" }`
  - `validateMove(ctx: MoveContext, move: TaskBoardMove): MoveVerdict`, where
    `MoveContext = { cards; columns; lanes?; heldBy?: Map<string,string>; selfId?: string }`.
    A card held by a different user gives `"held"`. Moving within the same bucket never trips
    WIP. Moving to a new column counts the target **without** the moving card.
  - `applyMove(cards: TaskBoardCard[], move: TaskBoardMove, columns, lanes?): TaskBoardCard[]`
    returns a new array. The card gets `column`/`lane` from `to`, and its position in the flat
    array is placed so that `bucketCards` yields it at `to.index`. All other cards keep their
    relative order. The input is not mutated.
  - `resolveDropIndex(rects: { id: string; top: number; height: number }[], pointerY: number, draggedId: string, current: number | null): number`
    implements the midpoint rule from spec §5. Over the dragged card's own rect, it returns
    `current`. Rects exclude nothing (the caller passes the live list including the placeholder).
  - `keyboardTarget(ctx: MoveContext, from: TaskBoardSlot, cardId: string, dir: "left" | "right" | "up" | "down" | "lane-up" | "lane-down"): TaskBoardSlot | null`
    returns the nearest **valid** slot in that direction, skipping collapsed/locked/full columns.
    Left/right keep the index clamped to the target bucket length.

  - `presenceReducer(state: PresenceState, event: unknown, now: number): PresenceState` is pure.
    - It ignores malformed or unknown events and returns the same reference.
    - `grab`: the earliest `at` wins, and a tie goes to the lower `userId` (string compare).
    - `hover` updates the hold only if it comes from the holder, and refreshes `lastSeen`.
    - `release` and `leave` clear the holds.
  - `expirePresence(state, now): PresenceState` drops peers and holds silent for `> LOCK_TTL_MS`.
  - `holderOf(state, cardId): string | null`
  - `createBroadcastChannelTransport(roomId: string): TaskBoardTransport & { close(): void }`
    posts to `new BroadcastChannel("taskboard:" + roomId)`. It does not echo its own messages
    (BroadcastChannel already does not).

### Task 7: Pointer and touch drag, guarded moves

**Files:**
- Create: `react/src/components/TaskBoard/useTaskBoardDrag.ts`,
  `react/src/components/TaskBoard/TaskBoardDragLayer.tsx`
- Modify: `TaskBoard.tsx`, `TaskBoardColumn.tsx`, `TaskBoardLaneGrid.tsx`, `TaskBoardCard.tsx`
- Test: `react/src/components/TaskBoard/TaskBoardDrag.test.tsx`

**Interfaces:**
- Consumes: `validateMove`, `applyMove`, `resolveDropIndex`, `bucketKey`.
- Produces: `useTaskBoardDrag(opts)`, which returns
  `{ drag: DragState | null; previewCards: TaskBoardCard[]; cardHandlers(card): {...pointer handlers}; cancel(reason?): void; pendingId: string | null }`.
  `DragState = { cardId; from: TaskBoardSlot; to: TaskBoardSlot | null; valid: boolean; x; y; grabOffset }`.
  It also exposes an `onDragTarget?(slot | null)` callback, which Task 9 uses to publish hovers.

**Behaviour:**
- **Grab:** a pointerdown on a card past a 4px threshold (mouse/pen) or a `TOUCH_GRAB_DELAY_MS`
  hold (touch) starts the drag. The card is captured with `setPointerCapture`.
- **Target:**
  - The bucket under the pointer is found through `document.elementFromPoint`, by walking up to
    `[data-bucket]`.
  - The index comes from `resolveDropIndex` over that bucket's `[data-card-id]` rects.
  - The verdict comes from `validateMove`.
- **Invalid target:** the bucket gets `data-drop="invalid"`, with a not-allowed tint and no line.
- **Preview:** `previewCards = applyMove(cards, {from, to})` when valid, so the order re-derives
  live. The origin slot becomes a dashed placeholder, and the clone renders through a portal at
  the pointer minus `grabOffset`.
- **Auto-scroll:** within 48px of a scroller edge, scroll by up to 16px/frame.
- **Drop:**
  - With no `onBeforeMove`, `onCardsChange(applyMove(...), move)` is called.
  - With `onBeforeMove`, `pendingId` is set and the preview stays. On `true`, the change is
    committed. On `false` or a throw, nothing is emitted and the card returns.
  - A drop on the origin slot emits nothing.
- **Esc** cancels.
- **Cards changing mid-drag:** the drag state keys on `cardId` and the slot is recomputed from
  the new `cards`, so the clone does not reset.
- **Reduced motion:** with `prefers-reduced-motion`, there are no slide transitions.

### Task 9: Collaboration in the component — presence, locks, remote ghosts

**Files:**
- Create: `react/src/components/TaskBoard/useTaskBoardCollab.ts`
- Modify: `TaskBoard.tsx`, `TaskBoardHeader.tsx`, `TaskBoardCard.tsx`, `TaskBoardDragLayer.tsx`

**Interfaces:**
- Consumes: Task 3 (`presenceReducer`, `expirePresence`, `holderOf`, constants), Task 4
  (`peerColor`, `getTaskBoardPeerTokens`), Task 7 (`onDragTarget`, `cancel`).
- Produces: `useTaskBoardCollab(transport?, currentUser?)`, which returns
  `{ presence: PresenceState; peers: TaskBoardUser[]; heldBy: Map<string,string>; grab(cardId): void; hover(cardId, slot): void; release(cardId, dropped): void }`.

**Behaviour:**
- **Lifecycle:**
  - On mount, subscribe and publish `presence` every `PRESENCE_HEARTBEAT_MS`.
  - Run `expirePresence` on a 1 s interval.
  - On unmount and `pagehide`, publish `leave` and unsubscribe. A handler call after unmount is a
    no-op (a ref guard).
- **Wiring to the local drag:**
  - My local drag start calls `grab()` with `at = Date.now()` and applies my own event to the
    reducer too.
  - `onDragTarget` calls a `hover()` throttled at `HOVER_THROTTLE_MS`.
  - A drop or cancel calls `release()`.
- **Losing a race:** if the reducer's holder for my dragged card stops being me (a peer's earlier
  grab arrived), call `cancel("held")`. The card springs back, and the inline chip shows
  `heldShort` for 2 s.
- **A card held by a peer:**
  - It is not draggable (`validateMove` gets `heldBy` and `selfId`; the card has `aria-disabled`
    and a `cursor-not-allowed`).
  - It is dimmed, with a ring in `peerColor` and the peer's `UserAvatar` badge.
  - It gets the `held` text as `title` and an sr-only description.
- **Remote ghost:** render a ghost in `TaskBoardDragLayer`, in an absolutely positioned overlay
  above the buckets. It sits at the hovered slot's rect, which is measured from
  `[data-bucket] [data-card-id]` or the bucket end, and is labelled with the peer's name. The
  ghost never changes `previewCards`, so my layout is untouched.
- **Header:** the header avatar stack shows `currentUser` + peers (max 5 + `+n`), with
  `aria-label` = `online`.
- **Without `transport`:** none of this runs. There are no timers.
