| 2026-08-20 | Design | Decorative highlight/glow overlays must be FULL-BLEED (`inset-0`) and fade to zero alpha inside their own box. A partial-size box with a linear gradient fades on one axis only, so its other edges cut off hard and render as visible rectangles — that was Panel `specularMode="halo"`. | 2026-08-20 | Tailwind | A helper that returns class strings must return ONE concern. `getSpecularClasses` returned paint *and* layout while every caller also applied its own layout, so `inset-0` fought `inset-x-0 top-0 h-[10px]` and emission order silently decided the winner. | 2026-08-20 | Design | Contrast on glass is a function of fill opacity, not text colour — CSS cannot see the backdrop. A `{color}-900` label needs ~85 % fill to stay legible over a dark photo; at 55 % it fails. Ship sheer presets, but document which one is safe over busy backdrops rather than trying to auto-correct. | glass.ts |

| 2026-08-20 | Design | A sweeping highlight needs shape, not just travel. A full-height rectangle sliding across reads as "a box moving" no matter how you tune the gradient. | 2026-08-20 | Design | An effect nobody can see reads as a broken toggle. `GlassBackground`'s shimmer (`white/0.08`, mostly off-container) and ambient glows (unsafelisted colour, 0.12 opacity) both technically rendered, so the demo toggles "did nothing". | 2026-08-20 | Tailwind | You cannot simulate a `:hover` state by passing the hover classes as a plain `className` — both rules target the same property at the same specificity, so the stylesheet's own order decides, not the class attribute. `.hover\:x:hover` wins over `.x` by specificity, which is why real hover works while the simulation showed no change. | 2026-08-20 | Design | An opacity step is a weak hover signal on a translucent control. | 2026-08-20 | Tailwind | **Never hand-write a variant class as raw CSS.** `.dark\:hover\:bg-blue-600\/45 { ... !important }` is a *plain class selector* — no `:where(.dark, .dark *)`, no `:hover`.
